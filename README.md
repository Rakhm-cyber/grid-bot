# Адаптивный парный грид-бот (OKX USDT Perpetual)

Бот реализует стратегию **парного грид-трейдинга на спреде** двух высококоррелированных фьючерсных активов (OKX, USDT Perpetual). Использует EMA логарифмического спреда как центр сетки, волатильность для расчёта шагов и продвинутый риск-менеджмент.

> **Важно:** Аналитика (поиск подходящих торговых пар) и бот работают **независимо**.
> Схема: `аналитика → пользователь проверяет пару → бот запускается на этой паре`

## Концепция стратегии

**Логарифмический спред** = `ln(price_base / price_quote)` колеблется вокруг скользящей средней (EMA). Бот:
1. Строит **сетку уровней** вокруг EMA на основе волатильности (σ).
2. При отклонении спреда от EMA **открывает парную позицию** рыночным ордером:
   - Спред выше EMA → **short base + long quote** (продаём спред)
   - Спред ниже EMA → **long base + short quote** (покупаем спред)
3. **Закрывает позицию** при возврате спреда к EMA (тейк-профит).
4. Стоп-лосс срабатывает при выходе спреда за `EMA ± stop_multiplier × σ`.

Все позиции — **кросс-маржинальные**, все ордера — **рыночные**.

## Быстрый старт

### 1. Установка зависимостей

```bash
# Создайте виртуальное окружение (рекомендуется)
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Linux/Mac

# Установите зависимости
pip install -r requirements.txt
```

### 2. Настройте API-ключи

Создайте файл `.env` в директории `okx_pair_bot/`:

```env
OKX_API_KEY=ваш_api_key
OKX_SECRET_KEY=ваш_secret_key
OKX_PASSPHRASE=ваша_passphrase
```

> **Получение API-ключей OKX:**
> Личный кабинет → API → Создать API-ключ
> Разрешения: чтение + торговля (не нужен вывод средств)

```bash
cd okx_pair_bot
python main.py --base ARBUSDT --quote ATOMUSDT
```

### 4. Запуск в боевом режиме

```bash
cd okx_pair_bot
python main.py --base ARBUSDT --quote ATOMUSDT --no-dry-run
```

Перед запуском бот запросит подтверждение (введите `YES`).

## Шаг 1: Аналитика (выбор пары)

Перед запуском бота нужно выбрать подходящую торговую пару. Аналитика запускается **отдельно** и не связана с ботом.

### 1.1. Загрузка исторических данных

```bash
# Загружает данные для всех монет из coins.txt
python run.py

# Или с параметрами
python run.py --days 180 --timeframes 15m 1h 4h
```

Данные сохраняются в `data/binance/{SYMBOL}_{TIMEFRAME}.csv`.

### 1.2. Расчёт парных метрик

```bash
python anal/corr_pairs_excel.py
```

Результат: `anal/output/corr_pairs.csv` с метриками для всех пар.

**Ключевые метрики:**
| Колонка | Описание | Хорошее значение |
|---------|----------|-----------------|
| `gate` | 1 = прошла фильтр коинтеграции | `= 1` |
| `final_score` | Итоговый балл | `> 0.5` |
| `hurst_month` | Степень mean reversion | `< 0.5` |
| `half_life_month` | Скорость возврата (свечи) | `50–500` |
| `coint_p_month` | p-value коинтеграции | `< 0.05` |

### 1.3. Критерии выбора пары

Хорошая пара для бота должна иметь:
- `gate = 1`
- `final_score > 0.5`
- `hurst_month < 0.45`
- `half_life_month` в диапазоне 50–500 (не слишком быстрый и не слишком медленный возврат)
- Оба инструмента должны быть доступны как USDT Perpetual на OKX

### 1.4. Полезные флаги аналитики

```bash
# Обновить данные и пересчитать
python anal/corr_pairs_excel.py --refresh-data

# Изменить ширину Z-score коридора
python anal/corr_pairs_excel.py --zscore-band 1.0

# Фильтр по half-life
python anal/corr_pairs_excel.py --hl-min 20 --hl-max 800
```

## Параметры конфигурации

Полное описание всех параметров `config.yaml`:

### Индикаторы

```yaml
base_timeframe: "1h"          # Таймфрейм (1m, 5m, 15m, 1h, 4h)

use_hl2_ema: true             # Использовать (high+low)/2 для EMA

volatility_type: "mad"        # mad (среднее абс. откл.) или std (стандартное)
```

### Опциональные функции сетки

```yaml
# Адаптивный шаг (зависит от краткосрочной/долгосрочной волатильности)
adaptive_step:
  enabled: false
  ratio_threshold_high: 1.2   # Если σ_short/σ_long > 1.2 — увеличить шаг
  multiplier_high: 1.5
  ratio_threshold_low: 0.8    # Если σ_short/σ_long < 0.8 — уменьшить шаг
  multiplier_low: 0.7
```

### Опциональные функции входа

```yaml
# Подтверждение входа (ждать закрытия свечи за уровнем)
entry_confirmation: false
confirmation_timeframe: "5m"

# Размер позиции по Z-Score (больше отклонение = больше позиция)
zscore_sizing: false
zscore_scale_factor: 1.5      # Множитель при |Z| 1.5–2.5
zscore_max_factor: 2.0        # Множитель при |Z| ≥ 2.5
```

### Опциональные функции выхода

```yaml
# Частичное закрытие позиции по пути к EMA
partial_tp:
  enabled: false
  levels:
    - fraction: 0.3            # Закрыть 30%...
      at_ratio: 0.5            # ...пройдя половину пути до EMA
    - fraction: 0.3
      at_ratio: 0.8

# Закрытие по времени
time_stop_enabled: false
max_hold_hours: 48

# Трейлинг-стоп
trailing_stop: false
```

### Риск-менеджмент

```yaml
max_leverage: 2.0             # Макс. плечо (сумма позиций / капитал)
max_loss_fraction: 0.05       # Допустимый убыток: 5% капитала
stop_loss_multiplier: 3.5     # Стоп при EMA ± 3.5σ
var_based_leverage: false     # VaR-лимит (автоматический расчёт плеча)
```

### Детектор аномалий

```yaml
anomaly_detector:
  volume_lookback_hours: 24       # Период для расчёта среднего объёма
  volume_spike_multiplier: 10.0   # Блокировка если объём > среднего в 10 раз
  max_allowed_spread_pct: 0.5     # Макс. bid-ask спред в %
  volatility_spike_threshold: 3.0 # Блокировка если σ выросла в 3 раза
  auto_resume_minutes: 60         # Автоматическая повторная проверка через 60 мин
```

## Архитектура бота

```
main.py (GridBot)
├── DataCollector      — загрузка OHLCV с OKX, расчёт EMA/σ/Z-Score
├── StrategyEngine     — построение сетки, сигналы входа/выхода
├── PositionManager    — рыночные ордера, синхронизация с OKX
├── RiskManager        — контроль экспозиции и риска
├── AnomalyDetector    — мониторинг аномалий, блокировка
├── SessionManager     — контроль 5/7-дневной сессии
└── BotDatabase        — SQLite: сделки, equity, сессии
```

### Цикл работы (каждые 5 секунд)

```
1. Получить SpreadSnapshot (текущий спред, EMA, σ, Z)
2. Проверить аномалии → заблокировать входы если есть
3. Проверить состояние сессии (5-й день, 7-й день)
4. Пересчитать сетку (если прошёл recalc_interval)
5. Проверить трейлинг-стопы для открытых позиций
6. Проверить тайм-стопы для открытых позиций
7. Проверить стоп-лосс (Z ≥ stop_multiplier)
8. Проверить тейк-профиты → закрыть позиции по рынку
9. Если нет аномалий → проверить сигнал входа → открыть позицию
10. Логировать состояние каждые 5 минут
```

## Управление сессией

Одна торговая сессия = максимум **7 дней**.

| День | Действие |
|------|----------|
| 1–4 | Нормальная торговля |
| 5 | Проверка целевой прибыли. Если PnL ≥ `target_profit_pct` × капитал → бот останавливается, позиции закрываются |
| 6–7 | Продолжает работу если цель не достигнута |
| 7 | Принудительное закрытие: позиции закрываются стремясь к безубытку. Общий убыток не должен превышать `max_exit_loss_pct` |

По завершении:
- Отчёт: `okx_pair_bot/session_report_{ID}.txt`
- График: `okx_pair_bot/equity_{ID}.png`
- Данные в БД: `okx_pair_bot/trades.db`

## Детектор аномалий

Бот автоматически блокирует **новые входы** при обнаружении:

1. **Всплеск объёма** — текущий объём в `volume_spike_multiplier` раз выше среднего
2. **Низкая ликвидность** — bid-ask спред шире `max_allowed_spread_pct`%
3. **Неактивный контракт** — биржа перевела инструмент в режим only-reduce
4. **Всплеск волатильности** — σ выросла в `volatility_spike_threshold` раз

При аномалии:
- Новые позиции не открываются
- Открытые позиции продолжают мониторинг (закрываются по TP/SL)
- В лог пишется предупреждение
- Через `auto_resume_minutes` — повторная проверка и автоснятие блокировки

## Риск-менеджмент

| Параметр | Описание |
|----------|----------|
| `max_leverage` | Суммарная экспозиция не превысит `capital × max_leverage` |
| `max_loss_fraction` | Совокупный потенциальный убыток ≤ 5% капитала |
| `stop_loss_multiplier` | Стоп при отклонении спреда на 3.5σ |
| `max_positions_per_side` | Не более 3 позиций в одном направлении |

### Восстановление после перезапуска

При перезапуске бот:
1. Подключается к OKX и считывает все открытые позиции
2. Восстанавливает состояние сетки (EMA, σ, уровни)
3. Для каждой открытой позиции корректирует тейк-профит на текущую EMA
4. Продолжает работу без потери данных

## FAQ

**Q: Как изменить торговую пару без правки конфига?**
A: `python main.py --base ETHUSDT --quote CRVUSDT`

**Q: Бот использует лимитные ордера?**
A: Нет. Исключительно рыночные ордера для гарантированного исполнения.

**Q: Можно запустить несколько пар одновременно?**
A: Запустите несколько экземпляров `main.py` с разными конфигами.

**Q: Данные сохраняются при перезапуске?**
A: Да. Позиции считываются с OKX, история в SQLite не теряется.

**Q: Как посмотреть историю сделок?**
A: `okx_pair_bot/trades.db` — стандартная SQLite база. Используйте DB Browser for SQLite или pandas:
```python
import sqlite3, pandas as pd
conn = sqlite3.connect("okx_pair_bot/trades.db")
df = pd.read_sql("SELECT * FROM trades ORDER BY timestamp DESC LIMIT 50", conn)
print(df)
```

**Q: Что такое `gate = 0` в аналитике?**
A: Пара не прошла фильтр коинтеграции или hurst. Такие пары **не рекомендуется** торговать ботом.

## Аналитический блок (справочно)

Аналитика в папке `anal/` работает **независимо** от бота.

```bash
# 1. Скачать данные
python run.py

# 2. Рассчитать метрики всех пар
python anal/corr_pairs_excel.py

# 3. Проверить результаты
# anal/output/corr_pairs.csv — открыть в Excel
```

Метрики (колонки CSV):
- `kendall_week1..week4`, `kendall_month` — ранговая корреляция
- `coint_p_week1..week4`, `coint_p_month` — p-value коинтеграции
- `half_life_month` — скорость возврата к среднему (свечи)
- `hurst_month` — показатель mean reversion (< 0.5 = хорошо)
- `zscore_in_band_month` — % времени спреда в коридоре ±1σ
- `gate` — прошла фильтр (1/0)
- `final_score` — итоговый балл (чем выше, тем лучше)
